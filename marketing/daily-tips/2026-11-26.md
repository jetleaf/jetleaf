### **Slide 5: Pro-Tip / Enterprise Best Practice**
* **Header**: `PRO-TIP`
* **Title**: Write Custom Business-Critical Health Indicators
* **Body**: Don't just check if the server is awake; ensure dependent services (DB pools, Redis, payment gateways) are operational.
* **Code Snippet**:
```dart
@Pod()
class DatabaseHealthIndicator implements HealthIndicator {
  final ConnectionPool _pool;
  
  DatabaseHealthIndicator(this._pool);

  @override
  Future<Health> check() async {
    final pingOk = await _pool.ping();
    return pingOk 
      ? Health.up().withDetail('activeConnections', _pool.activeSize).build()
      : Health.down().withDetail('error', 'Database ping timed out').build();
  }
}
```

## Ready-to-Copy Social Caption

Still returning static `{"status": "ok"}` JSON payloads from your backend `/health` route and calling it enterprise monitoring? 🛑

When running Dart backends in production, you need real-time visibility into **Isolate heap memory**, event loop lag, and connection pool health. If your database connection drops, your liveness probe shouldn't lie to Kubernetes.

With `jetleaf_actuator`, you get production-grade telemetry modeled after Spring Boot Actuator—out of the box:

✅ Native Isolate Memory & GC Metrics  
✅ K8s Liveness & Readiness Probes (`/actuator/health/liveness`)  
✅ Built-in Prometheus Scrape Endpoints  
✅ Extensible `@Pod` based custom `HealthIndicator` interfaces  

Here is how simple it is to add a custom DB health check:

```dart
@Pod()
class DatabaseHealthIndicator implements HealthIndicator {
  final ConnectionPool _pool;
  
  DatabaseHealthIndicator(this._pool);

  @override
  Future<Health> check() async {
    final pingOk = await _pool.ping();
    return pingOk 
      ? Health.up().withDetail('activeConnections', _pool.activeSize).build()
      : Health.down().withDetail('error', 'DB ping timed out').build();
  }
}
```
