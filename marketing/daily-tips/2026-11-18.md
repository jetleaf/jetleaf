### Slide 4: Deep Dive — Under the Hood
* **Header:** ARCHITECTURE DEEP DIVE
* **Title:** How `JetleafVM` Delivers Sub-100ms Iterations
* **Diagram Flow / Explanation:**
  1. **Resident Daemon (`libraries/jetleaf_tools`):** `jl dev` spawns a background supervisor VM process that remains persistent across code modifications.
  2. **Isolate Pre-Warming:** Jetleaf pre-allocates warm Dart worker Isolates running the core framework runtime ahead of time.
  3. **Incremental AST Diffing:** When a file is saved, the scanner isolates the exact delta, recompiles only the changed AST nodes, and hot-swaps the memory pointer inside the active isolate.
  4. **State Persistence:** Core IoC Pod singletons and database connection pools remain alive during code updates—no re-authenticating or reconnecting required.
