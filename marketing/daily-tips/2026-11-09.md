### Slide 2: The Architectural Problem
* **Title:** The Anti-Pattern: Spaghetti Injection & Global State
* **Subtext:** Manual object instantiation and global Service Locators make backend servers fragile, hard to test, and prone to startup order bugs.
* **Code Example (Anti-Pattern):**
```dart
// ❌ Anti-Pattern: Hardcoded coupling & global service locators
class OrderService {
  // Hardcoded dependency — impossible to mock cleanly
  final UserRepository repo = UserRepository(); 
  
  void process(String orderId) {
    // Global state lookup — hidden dependency side-effects
    final mailer = GetIt.I<MailerService>(); 
    mailer.sendReceipt(orderId);
  }
}
```

---

### Slide 3: The Jetleaf Way — Clean Code Example
* **Title:** The Jetleaf Way: Declarative `@Pod` Injection
* **Subtext:** Annotate your services with `@Pod()`. Jetleaf handles lifecycle, scope resolution, and constructor injection automatically.
* **Code Example:**
```dart
import 'package:jetleaf_core/jetleaf_core.dart';

@Pod()
class OrderService {
  final UserRepository userRepository;
  final MailerService mailerService;

  // ✅ Jetleaf automatically resolves and injects dependencies!
  OrderService(this.userRepository, this.mailerService);

  Future<void> processOrder(String orderId) async {
    final user = await userRepository.findUserByOrder(orderId);
    await mailerService.sendReceipt(user.email, orderId);
  }
}
```

---

### Slide 4: Deep Dive / How it Works Under the Hood
* **Title:** Under the Hood: Container Resolution Engine
* **Bullet Points:**
  1. **AST & Metadata Scanning:** Jetleaf inspects constructors during bootstrapping to resolve dependency signatures.
  2. **Directed Acyclic Graph (DAG):** Builds an execution topological sort to prevent circular dependencies before the server starts listening.
  3. **Isolate Pre-Warming:** Pod instances are initialized once per isolate worker using strict memory boundaries for maximum concurrency.
  4. **Lifecycle Execution:** Supports `@PostConstruct` and `@PreDestroy` hooks for automated cleanup.

### Slide 5: Pro-Tip / Enterprise Best Practice
* **Title:** Pro-Tip: Zero-Code Swapping with `@Profile`
* **Subtext:** Swap implementations between environments without touching application logic.
* **Code Example:**
```dart
abstract class MailerService {
  Future<void> sendReceipt(String email, String orderId);
}

@Pod()
@Profile('prod')
class SendGridMailer implements MailerService { ... }

@Pod()
@Profile('dev')
class DevConsoleMailer implements MailerService { ... }
```

## Ready-to-Copy Social Caption

Still manually wiring backend dependencies or using global Service Locators in your server-side Dart code? 🛑

If you come from Spring Boot or NestJS, manual dependency assembly feels like stepping back a decade. Hardcoded instances slow down unit testing, tightly couple your business domain, and introduce hidden state bugs.

Jetleaf brings **true Inversion of Control (IoC)** to the Dart backend ecosystem. 🍃

With simple declarative annotations like `@Pod()` and `@Profile()`, Jetleaf's core container handles dependency graph creation, instance lifecycle, and constructor injection automatically—before your server ever handles its first HTTP request.

Here is how clean your services look:

```dart
@Pod()
class OrderService {
  final UserRepository userRepository;
  final MailerService mailerService;

  // Automatically injected at runtime!
  OrderService(this.userRepository, this.mailerService);
}
```

### Why this changes server-side Dart:
✅ **Zero Service Locator anti-patterns** (`GetIt.I` lookups hidden deep inside method bodies).  
✅ **Environment-Aware Wiring** (`@Profile('dev')` vs `@Profile('prod')`).  
✅ **Sub-second hot reloads** powered by the `jl dev` resident daemon.  
✅ **Deterministic isolate memory boundaries.**

Stop reinventing backend infrastructure. Start building enterprise-ready backend applications with end-to-end type safety.

jl create backend_app
