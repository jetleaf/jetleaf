### Slide 2: The Architectural Anti-Pattern
**Header:** THE OLD WAY (Standard HTTP / Shelf)  
**Title:** The "Manual Parse & Check" Nightmare  

```dart
// ❌ 30+ lines of imperative parsing, null-checks, and error responses
Future<Response> handleCreateUser(Request request) async {
  final payload = jsonDecode(await request.readAsString());
  
  if (payload['email'] == null || !payload['email'].contains('@')) {
    return Response.badRequest(body: jsonEncode({'error': 'Invalid email'}));
  }
  if (payload['password'] == null || payload['password'].length < 8) {
    return Response.badRequest(body: jsonEncode({'error': 'Password too short'}));
  }
  
  // Business logic buried underneath boilerplate...
}
```

**Key Takeaway:** Imperative validation pollutes domain logic, creates inconsistent HTTP error formats, and leads to runtime type failures.

### Slide 3: The Jetleaf Way — Declarative & Type-Safe
**Header:** THE JETLEAF WAY  
**Title:** Declarative DTO Validation & Controllers  

```dart
// 1. Define Validated Request DTO
class CreateUserDto {
  @NotNull()
  @Email()
  final String email;

  @NotNull()
  @Size(min: 8, message: 'Password must be at least 8 characters')
  final String password;

  CreateUserDto({required this.email, required this.password});
}

// 2. Declarative Controller Endpoint
@RestController()
@RequestMapping('/api/v1/users')
class UserController {
  @PostMapping()
  Future<ResponseEntity<UserResponse>> createUser(
    @Valid() @RequestBody CreateUserDto dto,
  ) async {
    final user = await userService.register(dto);
    return ResponseEntity.created(user);
  }
}
```

### Slide 4: Under the Hood
**Header:** ARCHITECTURE DEEP DIVE  
**Title:** Request Lifecycle in `jetleaf_web`  

```
   HTTP Request  ──► [ Jetleaf Web Router ]
                            │
                            ▼
                     [ Jetson Parser ]  ──► Deserializes JSON to DTO
                            │
                            ▼
              [ jetleaf_validation Interceptor ]
                            │
             ┌──────────────┴──────────────┐
             │ Valid                       │ Invalid
             ▼                             ▼
   [ Exec Controller Method ]    [ MethodArgumentNotValidException ]
             │                             │
             ▼                             ▼
   Returns 201 Created          Returns 400 Bad Request (JSON)
```

1. **Jetson Engine:** Deserializes raw request bytes directly into strong-typed DTO instances.
2. **Validation Interceptor:** Executes AST-compiled reflection constraints before controller invocation.
3. **Short-Circuit Protection:** Invalid payloads fail fast *before* touching your service layer.

### Slide 5: Enterprise Best Practice
**Header:** PRO-TIP  
**Title:** Centralized Error Handling with `@ControllerAdvice`  

Never catch validation errors inside your controller. Handle them globally across your application using declarative exception handlers:

```dart
@ControllerAdvice()
class GlobalExceptionHandler {
  @ExceptionHandler([MethodArgumentNotValidException])
  ResponseEntity<ValidationErrorResponse> handleValidation(
    MethodArgumentNotValidException ex,
  ) {
    final errors = ex.bindingResult.fieldErrors
        .map((e) => FieldErrorDto(field: e.field, message: e.message))
        .toList();

    return ResponseEntity.status(HttpStatus.badRequest)
        .body(ValidationErrorResponse(status: 400, errors: errors));
  }
}
```

## Ready-to-Copy Social Caption

Still writing manual `if (json['email'] == null)` checks and string matching in your Dart backend controllers? 🛑

If you’re coming from Java (Spring Boot) or TypeScript (NestJS), writing imperative HTTP handlers in Dart can feel like stepping back a decade.

With **Jetleaf Web** (`jetleaf_web`) and **Jetleaf Validation** (`jetleaf_validation`), you get declarative, enterprise-grade REST APIs out of the box:

✅ Automatic JSON-to-DTO deserialization via **Jetson**  
✅ Strong-typed request annotations (`@RequestBody`, `@PathVariable`, `@RequestParam`)  
✅ Declarative schema validation (`@NotNull`, `@Email`, `@Size`, `@Pattern`)  
✅ Global exception interceptors (`@ControllerAdvice`)  

Here is how clean your controller layer looks:

```dart
@RestController()
@RequestMapping('/api/v1/users')
class UserController {
  @PostMapping()
  Future<ResponseEntity<UserResponse>> createUser(
    @Valid() @RequestBody CreateUserDto dto,
  ) async {
    final user = await userService.register(dto);
    return ResponseEntity.created(user);
  }
}
```

No manual status codes, no nested `if-else` guards, and zero context switching if you're building full-stack with Flutter.
