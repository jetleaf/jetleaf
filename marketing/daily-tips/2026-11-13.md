### Slide 2: The Architectural Problem / Anti-Pattern
* **Header:** The Polyglot Drift Tax
* **The Struggle:**
  * When your backend is written in Node.js, Go, or Python and your frontend is in Flutter, **every API change incurs a synchronization penalty**.
  * Hand-rolled OpenAPI specs drift from implementation.
  * Field renames (`user_id` vs. `userId`) crash production apps with runtime errors:
    ```text
    Unhandled Exception: type 'Null' is not a subtype of type 'String' in type cast
    ```
  * Engineers spend hours writing boilerplate serialization logic across two completely separate codebases.

### Slide 3: The Jetleaf Way — Clean Code Example
* **Header:** One Monorepo. One Language. Shared DTOs.
* **Code Walkthrough:**

```dart
// 1. packages/core_contracts/lib/src/dto/auth_dto.dart (Shared Package)
import 'package:jetleaf_validation/jetleaf_validation.dart';

class RegisterRequest {
  @NotNull()
  @Email(message: 'Must be a valid enterprise email')
  final String email;

  @NotNull()
  @Size(min: 8, message: 'Password must be at least 8 characters')
  final String password;

  const RegisterRequest({required this.email, required this.password});
}

// 2. server/lib/src/controllers/auth_controller.dart (Jetleaf Backend)
import 'package:jetleaf_web/jetleaf_web.dart';
import 'package:core_contracts/core_contracts.dart';

@RestController()
@RequestMapping('/api/v1/auth')
class AuthController {
  @PostMapping('/register')
  Future<ResponseEntity<UserResponse>> register(
    @Valid() @RequestBody() RegisterRequest request,
  ) async {
    // request.email is statically typed, validated, and sanitized
    return ResponseEntity.created(UserResponse(id: 'usr_99', email: request.email));
  }
}
```

### Slide 4: Deep Dive / How it Works Under the Hood
* **Header:** Zero-Cost Shared Contracts with `jetson`
* **Under the Hood:**
  1. **Dart Workspaces:** A single `pubspec.yaml` monorepo links your Flutter app and Jetleaf backend to `packages/core_contracts`.
  2. **Compile-Time Binding:** Jetleaf’s AST analyzer detects `@RequestBody() RegisterRequest` and wires it to the `jetson` deserialization engine without runtime mirrors (`dart:mirrors`).
  3. **Deterministic Declarative Validation:** `@Valid()` executes constraint validators (`@NotNull`, `@Email`) *before* controller dispatch.
  4. **Frontend Reuse:** Flutter consumes the exact same `RegisterRequest` instance directly in `http.post` or `dio` requests. No manual JSON parsing code-gen.

### Slide 5: Pro-Tip / Enterprise Best Practice
* **Header:** Pro-Tip: Enforce API Contracts in CI
* **Content:**
  * Because your client and server share pure Dart packages, breaking API changes are caught at **compile time**—not in production.
  * Add a single root check to your CI/CD pipeline:
    ```bash
    dart pub workspaces list
    dart analyze --fatal-infos
    ```
  * **The Result:** If a backend engineer renames a field in `RegisterRequest`, Flutter’s UI immediately fails compilation in CI before any code merges to `main`.
  * **Context-Switching Cost = 0.**
