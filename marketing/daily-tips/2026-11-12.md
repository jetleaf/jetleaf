### **Slide 2: The Architectural Problem / Anti-Pattern**

* **Header:** THE ANTI-PATTERN
* **Title:** Fake Health Checks & Silent Isolate Memory Leaks
* **Body:** 
  Most Dart HTTP servers rely on manual, hardcoded `/health` endpoints that return `200 OK` even when the database pool is dead or an isolate is suffering severe heap bloat.
* **Bad Code Snippet:**
```dart
// ❌ Dangerous: Hardcoded health checks lie to Kubernetes load balancers
app.get('/health', (req, res) {
  // Returns HTTP 200 even if Database connection is severed!
  // No insight into Isolate RSS memory, GC pause times, or thread pool exhaustion.
  return res.json({'status': 'UP'});
});
```
* **Callout:** When your server fails silently inside production containers, Kubernetes can't auto-heal your instances.

### **Slide 4: Deep Dive / How it Works Under the Hood**

* **Header:** UNDER THE HOOD
* **Title:** How `jetleaf_actuator` Inspects Dart Isolates
* **Diagram Flow / Bullet Points:**
  1. **Isolate Diagnostics:** Direct low-level inspection of `Isolate.current` memory heap, allocated RSS, dynamic stack size, and active event-loop latency.

  4. **Prometheus & JSON Exporters:** Generates enterprise-ready metrics compatible with Grafana, Datadog, and Kubernetes probes out of the box.

### **Slide 5: Pro-Tip / Enterprise Best Practice**

* **Header:** PRO-TIP
* **Title:** Custom Health Indicators for Kubernetes Probes
* **Body:** Build custom health checks by implementing `HealthIndicator` and decorating with `@Pod`.
* **Pro Code Snippet:**
```dart
import 'package:jetleaf_core/jetleaf_core.dart';
import 'package:jetleaf_actuator/jetleaf_actuator.dart';

@Pod()
class PostgresHealthIndicator implements HealthIndicator {
  final DatabaseConnectionPool _pool;
  
  PostgresHealthIndicator(this._pool);

  @override
  Future<Health> health() async {
    final isAlive = await _pool.ping();
    if (isAlive) {
      return Health.up().withDetail('pool_connections', _pool.activeConnections).build();
    }
    return Health.down().withDetail('error', 'Database connection timeout').build();
  }
}
```
* **Best Practice:** Separate your endpoints into `/actuator/health/liveness` (is container alive?) and `/actuator/health/readiness` (can container accept traffic?).

Here is how simple it is to write a production-grade health indicator in Jetleaf:

```dart
@Pod()
class DatabaseHealthIndicator implements HealthIndicator {
  final DatabasePool _pool;

  DatabaseHealthIndicator(this._pool);

  @override
  Future<Health> health() async {
    final isAlive = await _pool.ping();
    return isAlive 
      ? Health.up().withDetail('connections', _pool.active).build()
      : Health.down().withDetail('error', 'Pool unreachable').build();
  }
}
```
