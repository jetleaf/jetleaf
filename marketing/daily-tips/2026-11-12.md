### Slide 3: The Jetleaf Way — Clean Code Example
* **Header:** THE JETLEAF WAY 🍃
* **Title:** Instant Isolate Metrics & Dynamic Health Probes
* **Code Snippet:**

```dart
import 'package:jetleaf/jetleaf.dart';
import 'package:jetleaf_actuator/jetleaf_actuator.dart';

@Pod()
class DatabaseHealthIndicator implements HealthIndicator {
  final DatabaseConnectionPool _pool;

  DatabaseHealthIndicator(this._pool);

  @override
  Future<Health> checkHealth() async {
    final isConnected = await _pool.ping();
    if (!isConnected) {
      return Health.down().withDetail('reason', 'Database ping timeout').build();
    }
    return Health.up()
        .withDetail('active_connections', _pool.activeConnections)
        .withDetail('idle_connections', _pool.idleConnections)
        .build();
  }
}
```

### Slide 4: Deep Dive / How it Works Under the Hood
* **Header:** INSIDE THE ENGINE ⚙️
* **Title:** How `jetleaf_actuator` Exposes Isolate Telemetry
* **Diagram / Flow:**
  1. **IoC Auto-Discovery:** `jetleaf_actuator` scans the IoC container for all implementations of `HealthIndicator`.
  2. **Dart VM Service Interop:** Directly polls Dart runtime primitives (`Isolate.current`, heap allocation metrics, GC events).
  3. **Aggregated Diagnostics:** Combines framework health + custom pod indicators into deterministic endpoints:
     * `/actuator/health` — Aggregate status & component checks.
     * `/actuator/metrics` — Isolate memory usage, active request counts, event loop latency.
     * `/actuator/info` — App version, active profiles (`production`, `staging`), git commit hash.

### Slide 5: Pro-Tip / Enterprise Best Practice
* **Header:** ENTERPRISE PRO-TIP 💡
* **Title:** Kubernetes Probes & Prometheus Integration
* **Key Advice:**
  * Separate public APIs from sensitive internal metrics by binding `/actuator/*` endpoints to an isolated internal port or securing them with `@PreAuthorize`.
  * Map Kubernetes probes directly:
    * **Liveness Probe:** `/actuator/health/liveness` (Checks Isolate event loop responsiveness).
    * **Readiness Probe:** `/actuator/health/readiness` (Checks DB connections, cache clusters, external dependencies).
