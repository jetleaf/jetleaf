### Slide 3: The Jetleaf Way (Clean Code)
*   **Header:** THE JETLEAF WAY: Declarative DTO Validation
*   **Subheader:** Let `jetleaf_web` and `jetleaf_validation` validate HTTP bodies automatically before your method runs:
*   **Code Block:**
```dart
// 1. Define your typed DTO with constraint annotations
class CreateUserDto {
  @NotNull(message: 'Name is required')
  @Size(min: 2, max: 50)
  final String name;

  @NotNull(message: 'Email is required')
  @Email(message: 'Must be a valid email address')
  final String email;

  @NotNull()
  @Size(min: 8, message: 'Password must be at least 8 characters')
  final String password;

  CreateUserDto({required this.name, required this.email, required this.password});
}

// 2. Controller automatically validates incoming payload
@RestController('/api/v1/users')
class UserController {
  @PostMapping()
  Future<ResponseEntity<UserResponse>> createUser(
    @Valid() @RequestBody() CreateUserDto dto,
  ) async {
    final user = await _userService.register(dto);
    return ResponseEntity.created(user);
  }
}
```
*   **Callout Box (Emerald Accent):** ✅ Zero manual status codes. Invalid requests automatically fail fast with HTTP 400 Bad Request and detailed field-level metadata.
*   **Footer:** `jetleaf.hapnium.com` • Slide 3/6

### Slide 4: Deep Dive (Under the Hood)
*   **Header:** HOW IT WORKS: Pipeline Execution Lifecycle
*   **Diagram / Architecture Flow:**
    1. **HTTP Request Arrives:** `POST /api/v1/users` (JSON payload)
    2. **Content Negotiation & Mapping:** `jetson` deserializes JSON to `CreateUserDto`.
    3. **Interceptor Evaluation (`@Valid`):** `jetleaf_validation` AST metadata scanner inspects fields against registered `ConstraintValidator` classes.
    4. **Validation Checkpoint:**
       * ❌ **Failed:** Interceptor aborts execution pipeline and instantly yields an RFC-7807 `ProblemDetails` HTTP 400 response.
       * ✅ **Passed:** Strongly-typed `CreateUserDto` instance is passed directly into `@RestController`.
*   **Key Advantage:** Your domain logic code only executes when payloads are **guaranteed** to be valid and type-safe.

### Slide 5: Enterprise Best Practice (Pro-Tip)
*   **Header:** PRO-TIP: Global Custom Validation & Standardized Errors
*   **Subheader:** Combine `@Valid` with custom annotations and uniform error structures.
*   **Code Block:**
```dart
// Define custom validation logic easily
class UniqueEmailValidator implements ConstraintValidator<UniqueEmail, String> {
  final UserRepository _userRepo;
  UniqueEmailValidator(this._userRepo); // Autowired IoC dependency!

  @override
  Future<bool> isValid(String? value, ValidationContext context) async {
    if (value == null) return true;
    return !(await _userRepo.existsByEmail(value));
  }
}

// Custom annotation usable anywhere in your full-stack app
@Constraint(validatedBy: UniqueEmailValidator)
class UniqueEmail {
  final String message;
  const UniqueEmail({this.message = 'Email address is already registered'});
}
```
*   **Enterprise Architecture Rule:** Inject your data repositories directly into validation constraints via Jetleaf's IoC container to execute async database uniqueness checks before hitting controller logic.

  }
}
