### Slide 2: The Architectural Problem / Anti-Pattern
* **Slide Title:** ❌ The "Spaghetti DI" Anti-Pattern in Server-Side Dart
* **Content:**
  Most Dart backend frameworks force you into one of two nightmares:
  1. **Manual Constructor Wiring:** Instantiating 40+ nested dependencies inside `main.dart` by hand.
  2. **Global Service Locators:** Using client-side state managers or unstructured global singletons on the server—leading to memory leaks across isolate lifecycles, untestable code, and race conditions.
* **Code Card (The Anti-Pattern):**
  ```dart
  // ❌ HARD TO TEST, UNMANAGED LIFECYCLE
  void main() {
    final db = DatabaseClient(connectString);
    final repo = UserRepository(db);
    final auth = AuthService(repo);
    final controller = UserController(auth); // Manual 5-level deep wiring!
  }
  ```

### Slide 3: The Jetleaf Way — Clean Code Example
* **Slide Title:** ✅ Declarative Dependency Injection with `@Pod`
* **Content:** Jetleaf's core IoC container inspects your constructors at startup and automatically injects dependencies. No manual factories, zero boilerplate.
* **Code Card (Jetleaf Enterprise Pattern):**
  ```dart
  import 'package:jetleaf_core/jetleaf_core.dart';

  abstract class PaymentGateway {
    Future<void> process(double amount);
  }

  @Pod()
  class StripeService implements PaymentGateway {
    @override
    Future<void> process(double amount) async {
      // Payment processing logic
    }
  }

  @Pod()
  class CheckoutService {
    final PaymentGateway paymentGateway;

    // Direct Constructor Injection: Jetleaf resolves PaymentGateway automatically!
    CheckoutService(this.paymentGateway);

    Future<void> completeOrder(double total) => paymentGateway.process(total);
  }
  ```

### Slide 4: Deep Dive / How It Works Under the Hood
* **Slide Title:** ⚡ Under the Hood: The Jetleaf IoC Lifecycle
* **Content & Flow Diagram:**
  1. **AST & Reflectable Discovery:** At app launch, `JetleafApplication.run()` scans your project graph for `@Pod` and `@Configuration` declarations.
  2. **Dependency Graph Resolution:** Pods are topologically sorted to eliminate circular dependencies before server initialization.
  3. **Scoped Lifecycle Hooks:** Pods respect startup hooks (`@PostConstruct`) and shutdown signals (`@PreDestroy`) cleanly when isolates receive `SIGINT` or `SIGTERM`.
* **Key Takeaway:** Zero global state mutation, 100% thread/isolate safe architecture.

### Slide 5: Enterprise Pro-Tip / Best Practice
* **Slide Title:** 💡 Enterprise Pro-Tip: Environment-Driven Pod Profiles
* **Content:** Swap entire implementation layers between local dev, staging, and production using `@Profile`.
* **Code Card:**
  ```dart
  @Pod()
  @Profile('dev')
  class MockPaymentGateway implements PaymentGateway {
    @override
    Future<void> process(double amount) async => print('Mocked \$$amount');
  }

  @Pod()
  @Profile('prod')
  class StripePaymentGateway implements PaymentGateway {
    @override
    Future<void> process(double amount) async => await stripeApi.charge(amount);
  }
  ```
* **Tip:** Execute `jl run --profile=prod` and Jetleaf automatically binds `StripePaymentGateway` across the container!
