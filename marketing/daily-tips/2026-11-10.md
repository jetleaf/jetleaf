### Slide 2: The Architectural Problem / Anti-Pattern
**Header:** THE OLD WAY (Manual Parsing Hell)  
**Headline:** Spaghetti Validation & Dynamic Maps  

```dart
// ❌ The Raw Shelf / Router Way
Future<Response> createUserHandler(Request req) async {
  final payload = jsonDecode(await req.readAsString());
  
  if (payload['email'] == null || !payload['email'].contains('@')) {
    return Response.badRequest(body: jsonEncode({'error': 'Invalid email'}));
  }
  if (payload['age'] == null || payload['age'] < 18) {
    return Response.badRequest(body: jsonEncode({'error': 'Must be 18+'}));
  }
  
  // 50 lines later: manual object instantiation...
  final user = User(email: payload['email'], age: payload['age']);
  return Response.ok(jsonEncode(user.toJson()));
}
```
**Takeaway:** Fragile, un-typed dynamic maps, duplicated validation rules, and error responses scattered across every handler.

### Slide 3: The Jetleaf Way — Clean Code Example
**Header:** THE JETLEAF WAY  
**Headline:** Declarative Endpoints + Auto-Validated DTOs ✨  

```dart
// ✅ DTO with Declarative Validation
class CreateUserDto {
  @NotNull()
  @Email(message: 'Must be a valid email address')
  final String email;

  @NotNull()
  @Min(18, message: 'User must be at least 18 years old')
  final int age;

  CreateUserDto({required this.email, required this.age});
}

// ✅ Controller with Built-in Validation Pipeline
@RestController('/api/v1/users')
class UserController {
  @PostMapping()
  Future<ResponseEntity<User>> createUser(
    @Valid() @RequestBody() CreateUserDto dto,
  ) async {
    final user = await _userService.register(dto.email, dto.age);
    return ResponseEntity.created(user);
  }
}
```

### Slide 4: Deep Dive / How It Works Under the Hood
**Header:** UNDER THE HOOD  
**Headline:** How Jetleaf Intercepts & Validates Requests  

```
[ Incoming Request ] ➡️ HTTP POST /api/v1/users {"email": "invalid", "age": 16}
         │
         ▼
[ Jetleaf Web Dispatcher ] ── (Resolves Route & Content-Type)
         │
         ▼
[ Jetson Serializer ] ────── (Deserializes Raw JSON ➡️ CreateUserDto Instance)
         │
         ▼
[ Jetleaf Validation ] ──── (Inspects AST & Annotations: @Email, @Min)
         │
         ├─ ❌ Invalid ➡️ Intercepts & throws MethodArgumentNotValidException
         └─ ✅ Valid   ➡️ Passes strongly-typed DTO directly into your method
```

**Key Benefit:** Invalid requests **never** hit your controller logic. Your domain services receive 100% clean, validated data types.

### Slide 5: Pro-Tip / Enterprise Best Practice
**Header:** ENTERPRISE PRO-TIP  
**Headline:** Standardize Errors with `@ControllerAdvice` 🛡️  

Centralize endpoint validation failures into standard **RFC 7807 Problem Details** automatically across your entire server:

```dart
@ControllerAdvice()
class GlobalExceptionHandler {

  @ExceptionHandler(MethodArgumentNotValidException)
  ResponseEntity<ProblemDetails> handleValidationError(
    MethodArgumentNotValidException ex,
  ) {
    final fieldErrors = ex.errors.map((e) => {
      'field': e.field,
      'message': e.message,
    }).toList();

    return ResponseEntity.badRequest().body(
      ProblemDetails(
        type: 'https://api.myapp.com/errors/validation',
        title: 'Validation Failure',
        status: 400,
        detail: 'One or more request parameters failed validation.',
        invalidParams: fieldErrors,
      ),
    );
  }
}
```

## Ready-to-Copy Social Caption

Still manually checking `if (json['email'] == null)` in your Dart backend HTTP handlers? 🛑

If you’re coming from Java Spring Boot (`@Valid`) or NestJS (`class-validator`), you know how painful manual request validation can be when writing server-side Dart code.

With Jetleaf (`jetleaf_web` + `jetleaf_validation`), request parsing and parameter validation become completely declarative:

1️⃣ Define your DTO with validation annotations (`@Email`, `@NotNull`, `@Min`, `@Size`).  
2️⃣ Annotate your controller endpoint with `@Valid @RequestBody`.  
3️⃣ Let Jetleaf handle JSON parsing, type casting, and constraint checking before your controller code even executes!

If validation fails, Jetleaf short-circuits the request and returns structured validation errors via your central `@ControllerAdvice` handler.

No manual `Map<String, dynamic>` indexing.  
No scattered `if/else` checks.  
Just 100% typed, resilient Dart backends.

💡 **CLI Quickstart:**
```bash
dart pub global activate jetleaf_tools
jl create my_web_api --template=web
```
