### Slide 4: Deep Dive / How it Works Under the Hood
**[Headline]** Inside the `JetleafVM` Daemon Architecture 🧠  
**[Diagram / Bullet Breakdown]**
1. **Resident Process Daemon:** Running `jl dev` spawns a background `JetleafVM` daemon that maintains a persistent Dart Kernel Compiler engine.
2. **Isolate Pre-Warming:** Jetleaf pre-allocates worker isolates in memory ahead of time, eliminating the runtime isolate instantiation delay.
3. **Differential Dill Patching:** On save, `jetleaf_tools` calculates the precise AST delta, injects hot kernel patches into the active isolate, and re-links your `@Pod` lifecycle trees.
4. **State-Aware Teardown:** Controllers and services are re-instantiated seamlessly while database driver sockets remain warm and open.

### Slide 5: Pro-Tip / Enterprise Best Practice
**[Headline]** Enterprise Pro-Tip: Clean Hot-Swapping with `@PostConstruct` 🔥  
**[Body Text]** To prevent resource leaks (like duplicate stream subscriptions) during sub-second hot reloads, leverage Jetleaf lifecycle hooks.

```dart
@Pod()
class RealtimeNotificationService {
  late final StreamController<Event> _controller;

  @PostConstruct()
  void init() {
    // Executed clean upon initial boot & hot isolate re-link
    _controller = StreamController<Event>.broadcast();
  }

  @PreDestroy()
  void dispose() {
    // Gracefully closed when JetleafVM swaps class definitions
    _controller.close();
  }
}
```
* **Result:** Zero dangling listeners, clean memory overhead, and instant feedback.

Tired of waiting 3 to 8 seconds every single time you edit a Dart backend route? 🐢 🛑

If you’re a Flutter developer working on server-side Dart, you know the pain: running `dart run bin/server.dart`, killing the process, waiting for the AST compiler, tearing down database connections, and re-parsing models... just to test a single line of business logic.

That feedback loop breaks your flow state.

Enter **Jetleaf Tools** (`jetleaf_tools`) and the **JetleafVM Resident Daemon** ⚡️

With `jl dev`, Jetleaf brings Flutter-style, sub-100ms hot reload directly to your backend application:

✨ **Isolate Pre-Warming:** Worker isolates are pre-cached in memory before you even hit save.
✨ **Differential Kernel Patching:** Only updated AST nodes are compiled and injected.
✨ **State-Aware Re-Linking:** `@RestController` annotations and `@Pod` dependencies re-link dynamically while database connection pools stay warm.

Here is how simple it is to elevate your developer velocity today:

```bash
# Activate the CLI
dart pub global activate jetleaf_tools

# Run your application with sub-second hot reload
jl dev
```

Pair this with `@PostConstruct` and `@PreDestroy` lifecycle hooks, and you get zero resource leaks, clean teardowns, and pure, uninterrupted developer flow.
