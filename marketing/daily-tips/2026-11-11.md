### Slide 2: The Architectural Problem
**Title:** The Cold-Start Dev Loop Fatigue 🐢  
**Content:**  
Standard backend Dart development often suffers from sluggish edit-compile-run cycles:
- **Process Spawning Overhead:** Standard `dart run bin/server.dart` re-allocates memory, re-parses imports, and boots dynamic runtime reflective metadata on *every single save*.
- **State Wiping:** In-memory session states, cached DI singletons, and DB connection pools drop, forcing cold re-initializations (2–5s latency).
- **Broken Flow State:** Frontend Flutter app hot reloads in 200ms, while your Dart backend takes seconds to catch up.

### Slide 3: The Jetleaf Way (Clean CLI & DX)
**Title:** Instant Feedback with `jl dev` 🔥  
**Content:**  
The Jetleaf CLI (`jetleaf_tools`) manages a background resident daemon (**JetleafVM**) that pre-warms isolate workers and applies state-preserving hot reloads instantly.

```bash
# Activate Jetleaf DevTools once
$ dart pub global activate jetleaf_tools

# Launch resident dev server in your project root
$ jl dev
```
