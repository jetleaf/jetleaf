### Slide 2: The Architectural Problem / Anti-Pattern
* **Title:** The Production Black Box 📦
* **Subtitle:** Why traditional Dart servers fail in enterprise production environments.
* **Key Pain Points:**
  * **Invisible Heap Memory:** Dart Isolates manage independent garbage collectors. A silent memory leak in Isolate #3 goes undetected until Kubernetes issues an abrupt OOM-Killed `SIGKILL`.
  * **Boilerplate VM Hooks:** Exposing custom VM Service Protocol endpoints or scraping raw heap stats manually requires hundreds of lines of low-level `dart:developer` plumbing.
  * **Dummy Health Checks:** Most Dart web APIs return a hardcoded `{"status": "ok"}` on `/health` even when database pools are exhausted or downstream services are dead.

### Slide 3: The Jetleaf Way — Clean Code Example
* **Title:** Instant Production Telemetry ⚡
* **Subtitle:** Enable standard production actuator endpoints with `jetleaf_actuator`.
* **Code Example (Dart):**

```dart
import 'package:jetleaf/jetleaf.dart';
import 'package:jetleaf_actuator/jetleaf_actuator.dart';

@Configuration()

void main() async {
  await JetleafApplication.run(appModule: AppModule);
}
```

* **Footnote:** *Exposes automated, production-ready telemetry at `/actuator/health`, `/actuator/metrics`, and `/actuator/isolate` immediately.*

### Slide 4: Deep Dive / How It Works Under the Hood
* **Title:** Under the Hood: Zero-Overhead Sampling 🔬
* **Key Architectural Insights:**
  * **Non-Blocking Isolate Metrics:** `jetleaf_actuator` queries Dart's runtime memory statistics without pausing event loops or interrupting active isolate worker pools.
  * **K8s-Native Readiness & Liveness:** `/actuator/health/liveness` asserts process survival, while `/actuator/health/readiness` automatically inspects critical Pod dependencies before accepting ingress traffic.
  * **Aggregated Telemetry Engine:** Normalizes isolate heap size (`isolate.heap.used`), external allocations (`isolate.memory.external`), and total active isolate threads into standard JSON or Prometheus formats.

### Slide 5: Pro-Tip / Enterprise Best Practice
* **Title:** Custom Health Indicators 💡
* **Subtitle:** Never send traffic to an unhealthy Pod again.
* **Code Example (Dart):**

```dart
@Pod()
class DatabaseHealthIndicator implements HealthIndicator {
  final PostgreSQLClient _db;

  DatabaseHealthIndicator(this._db);

  @override
  Future<Health> checkHealth() async {
    final isConnected = await _db.ping();
    if (!isConnected) {
      return Health.down(reason: 'PostgreSQL connection pool exhausted');
    }
    return Health.up(details: {'database': 'PostgreSQL 16', 'pool_size': 10});
  }
}
```

* **Best Practice:** Register custom `HealthIndicator` pods into Jetleaf's IoC container. Jetleaf automatically aggregates all indicator results into the primary `/actuator/health` endpoint payload!
