### Slide 2: The Architectural Problem / Anti-Pattern
* **Header:** The "Status: OK" Illusion
* **The Anti-Pattern:**
  ```dart
  // ❌ Anti-Pattern: Manual, shallow health checks
  router.get('/health', (req) => Response.ok('{"status": "ok"}'));
  ```
* **Why it breaks in Enterprise Production:**
  * Zero visibility into Dart Isolate Heap & RSS memory bloat.
  * No standard Kubernetes Liveness/Readiness probe segregation.
  * No real-time metric exposure (GC pauses, active event-loop latency, HTTP connection counts).
  * Outages happen long before your custom static endpoint ever responds with a 500.

---

### Slide 3: The Jetleaf Way — Clean Code Example
* **Header:** Real-Time Telemetry & Custom Health Indicators
* **Dart Code Snippet:**
  ```dart
  import 'package:jetleaf_core/jetleaf_core.dart';
  import 'package:jetleaf_actuator/jetleaf_actuator.dart';

  @Pod()
  class PostgresHealthIndicator implements HealthIndicator {
    final DatabasePool _pool;

    PostgresHealthIndicator(this._pool);

    @override
    Future<Health> checkHealth() async {
      final isHealthy = await _pool.ping();
      if (isHealthy) {
        return Health.up()
            .withDetail('database', 'PostgreSQL 16')
            .withDetail('activeConnections', _pool.activeCount)
            .build();
      }
      return Health.down()
          .withDetail('error', 'Connection pool exhausted')
          .build();
    }
  }
  ```

### Slide 4: Deep Dive / How it Works Under the Hood
* **Header:** How `jetleaf_actuator` Inspects Dart Isolates
* **Key Steps:**
  1. **Isolate VM Telemetry:** Hooks directly into `dart:developer` and runtime isolate probes to track Memory Heap, RSS, and Garbage Collection cycles in non-blocking background threads.
  2. **Automated Health Aggregation:** Discovers all `@Pod` classes implementing `HealthIndicator` and evaluates them concurrently during `/actuator/health` polls.
  3. **Prometheus & OpenTelemetry Ready:** Exposes `/actuator/metrics` formatted for instant ingestion into Prometheus, Grafana, and Datadog without heavy third-party APM agents.

---

### Slide 5: Pro-Tip / Enterprise Best Practice
* **Header:** Kubernetes Readiness Probes & Dynamic YAML Controls
* **Best Practice:** Enable granular endpoint exposure directly inside your `application.yaml`:
  ```yaml
  management:
    endpoints:
      web:
        exposure:
          include: "health,metrics,info,isolates"
    health:
      probes:
        enabled: true # Exposes /actuator/health/liveness & /actuator/health/readiness
  ```
* **Enterprise Rule:** Keep `/actuator/health/liveness` lightweight for pod restarts; bind heavy database/third-party service checks to `/actuator/health/readiness`.
