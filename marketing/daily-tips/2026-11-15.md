### Slide 2: The Architectural Problem / Anti-Pattern
### The Anti-Pattern: Manual Retry Spaghetti

When upstream third-party APIs (Stripe, Twilio, microservices) flicker, developers often write this:

```dart
// ❌ UGLY, FRAGILE, POLLUTES BUSINESS LOGIC
Future<PaymentResult> chargeCustomer(String id) async {
  int attempts = 0;
  int delayMs = 200;
  while (attempts < 3) {
    try {
      return await stripeClient.charge(id);
    } on SocketException catch (e) {
      attempts++;
      if (attempts >= 3) rethrow;
      await Future.delayed(Duration(milliseconds: delayMs));
      delayMs *= 2; // Manual exponential backoff
    }
  }
  throw PaymentFailedException();
}
```
**Why this hurts production:**
- High boilerplate across dozens of service methods.
- Blocks or clutters event execution loops.
- Fallback logic is tightly coupled or entirely forgotten.
- Zero telemetry/metrics out of the box.

### Slide 3: The Jetleaf Way — Clean Code Example
### Declarative Fault Tolerance with `jetleaf_retry`

Jetleaf extracts resilience into declarative Pod proxies with built-in recovery fallbacks:

```dart
import 'package:jetleaf/jetleaf.dart';
import 'package:jetleaf_retry/jetleaf_retry.dart';

@Pod()
class BillingService {
  final PaymentGatewayClient _gateway;

  BillingService(this._gateway);

  @Retryable(
    include: [GatewayTimeoutException, SocketException],
    maxAttempts: 3,
    backoff: Backoff(delay: 300, multiplier: 2.0, maxDelay: 2000),
    recover: #fallbackPaymentProcessing,
  )
  Future<PaymentReceipt> processTransaction(PaymentRequest request) async {
    return await _gateway.execute(request);
  }

  // Graceful degradation when all 3 attempts fail
  PaymentReceipt fallbackPaymentProcessing(
    PaymentRequest request, 
    Exception error,
  ) {
    return PaymentReceipt.queued(request.id, status: 'QUEUED_FOR_RECONCILIATION');
  }
}
```

### Slide 4: Deep Dive / How it Works Under the Hood
### Behind the Scenes: AST Interception & Isolate Proxies

How Jetleaf handles `@Retryable` without blocking your isolate:

```
[ Incoming Request ]
         │
         ▼
[ Jetleaf IoC Container ]
         │ (Wraps Pod in Dynamic Invocation Proxy)
         ▼
┌────────────────────────────────────────────────────────┐
│  RetryProxyInterceptor                                 │
│  ├── Invokes target method                             │
│  ├── Catches registered exceptions                     │
│  ├── Calculates exponential jitter:                    │
│  │     t = delay * (multiplier ^ attempt) + random()   │
│  ├── Schedules non-blocking Timer on Dart Event Loop   │
│  └── Dispatches to @Recover symbol if attempts == max  │
└────────────────────────────────────────────────────────┘
```

1. **Zero Thread Blocking**: Uses Dart's native microtask & timer queue—no isolates are stalled during backoff delays.
2. **Type-Safe Recovery**: The `#fallbackPaymentProcessing` handler receives the original arguments plus the thrown exception for auditable degradation.

## Ready-to-Copy Social Caption

Stop writing fragile `while` loops and manual `Future.delayed` backoffs to handle intermittent API failures in Dart. 🛑

In distributed systems, network blips, third-party API rate limits, and transient timeouts are inevitable. But cluttering your clean domain services with nested `try/catch` retry logic makes code unreadable, difficult to test, and prone to edge-case bugs.

With **Jetleaf** (`jetleaf_retry`), you get enterprise-grade, declarative fault tolerance in a single annotation:

```dart
@Pod()
class BillingService {
  final PaymentGatewayClient _gateway;

  BillingService(this._gateway);

  @Retryable(
    include: [GatewayTimeoutException, SocketException],
    maxAttempts: 3,
    backoff: Backoff(delay: 300, multiplier: 2.0),
    recover: #fallbackPaymentProcessing,
  )
  Future<PaymentReceipt> processTransaction(PaymentRequest request) async {
    return await _gateway.execute(request);
  }

  PaymentReceipt fallbackPaymentProcessing(
    PaymentRequest request, 
    Exception error,
  ) {
    return PaymentReceipt.queued(request.id, status: 'QUEUED_FOR_RECONCILIATION');
  }
}
```

⚡ **Why this is a game-changer for Dart backend development:**
1️⃣ **Clean Architecture**: Resilience rules sit as declarative metadata on your methods—keeping your core business logic pristine.
2️⃣ **Non-Blocking Backoff**: Interceptors schedule execution against Dart's native event loop with zero thread or isolate stalling.
3️⃣ **Type-Safe Recovery**: Gracefully degrade service without leaking unhandled exceptions to your HTTP handlers.
4️⃣ **Production Observability**: Fully integrated with `jetleaf_actuator` to stream retry and recovery metrics straight to Prometheus or Datadog.
