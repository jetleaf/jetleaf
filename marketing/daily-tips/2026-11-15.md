### Slide 2: The Architectural Problem (Anti-Pattern)
* **Header:** The Spaghetti Retry Pattern
* **Sub-header:** What enterprise Dart services usually look like:
* **Code Graphic (Imperative / Flawed):**
```dart
// ❌ Cluttered, fragile, manual retry logic
Future<PaymentResult> processPayment(Order order) async {
  int attempts = 0;
  while (attempts < 3) {
    try {
      return await paymentGateway.charge(order);
    } catch (e) {
      attempts++;
      if (attempts >= 3) rethrow;
      await Future.delayed(Duration(seconds: attempts * 2));
    }
  }
  throw PaymentException('Failed after retries');
}
```
* **Pain Points:** Boilerplate pollution, unhandled edge cases, lack of backoff jitter, non-reusable across services, untestable fallback paths.

---

### Slide 3: The Jetleaf Way — Clean Code Example
* **Header:** Declarative Resilience with `jetleaf_retry`
* **Sub-header:** Zero boilerplate. Typed exception matching. Built-in fallbacks.
* **Code Graphic (Declarative / Clean):**
```dart
import 'package:jetleaf_core/jetleaf_core.dart';
import 'package:jetleaf_retry/jetleaf_retry.dart';

@Pod()
class PaymentService {
  final PaymentGateway gateway;

  PaymentService(this.gateway);

  @Retryable(
    maxAttempts: 3,
    delayMs: 500,
    multiplier: 2.0, // Exponential Backoff
    retryFor: [NetworkException, TimeoutException],
  )
  Future<PaymentResult> processPayment(Order order) async {
    return await gateway.charge(order);
  }

  @Recover()
  Future<PaymentResult> fallbackPayment(NetworkException e, Order order) async {
    return PaymentResult.queuedForAsyncProcessing(order.id);
  }
}
```

---

### Slide 4: How It Works Under the Hood
* **Header:** Under the Hood: IoC Interceptors & Backoff Engines
* **Key Mechanics:**
  1. **AOP Method Proxies:** `jetleaf_core` wraps `@Retryable` pods in dynamic proxy invocation handlers during container instantiation.
  2. **Exception Filtering:** The proxy inspects thrown errors against `retryFor`. Non-matching exceptions fail fast without retrying.
  3. **Exponential Backoff Engine:** Calculates delays via `delayMs * (multiplier ^ attempt)` with randomized jitter to prevent thundering herd problems in microservice clusters.
  4. **State-Free Recovery Routing:** If attempts exhaust, Jetleaf routes execution to the matching `@Recover` method signature seamlessly.

### Slide 5: Enterprise Pro-Tip
* **Header:** 💡 Pro-Tip: YAML-Driven Retry Policies
* **Sub-header:** Never hardcode timeout policies in your codebase. Externalize to `application.yaml`:

```yaml
jetleaf:
  retry:
    payment-service:
      max-attempts: 5
      delay-ms: 1000
      multiplier: 1.5
      jitter: 0.2
```

```dart
@Retryable(policy: 'jetleaf.retry.payment-service')
Future<PaymentResult> processPayment(Order order) async { ... }
```
* **Takeaway:** Change retry strategies across `dev`, `staging`, and `production` profiles without recompiling a single line of Dart code.
