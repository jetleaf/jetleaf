### Slide 2: The Architectural Problem
* **Header:** The Cold-Restart Flow Killer
* **Body Text:** 
  Standard Dart backend development relies on `dart run bin/server.dart` watching file changes. Every change triggers a cold process spawn:
  - 🛑 **3–5s latency** per change to recompile source files.
  - 🛑 **Dropped HTTP connections** during active frontend testing.
  - 🛑 **Destroyed isolate memory** and reset local caches.
  - 🛑 Context switching that destroys developer flow.
* **Visual Elements:** Red warning accent badge (`#EF4444`). Wireframe schematic showing a broken loop cycle with slow compile clock icons.

### Slide 4: Under the Hood
* **Header:** How `JetleafVM` Pre-Warms Your Engine
* **Diagram Structure:**
  1. **Resident Daemon:** `JetleafVM` stays alive across builds, holding warm Dart isolates ready in memory.
  2. **Incremental Compiler:** Only compiles changed AST diffs using Kernel bytes.
  3. **IoC Pod State Refresh:** `jetleaf_core` injects updated method signatures into live `@Pod` singletons without unwinding the application context or closing DB pools.
* **Visual Elements:** Architectural flow diagram showing `AST Patch` ➔ `Kernel Bytes` ➔ `Pre-Warmed Isolate` ➔ `Live Pod State preserved`.
